Validity audit · 10 September 2026 · all seven fixes applied

What Nomad Radar actually measures

I checked whether the index measures digital-nomad activity or something else that happens to correlate with it. It was partly the second thing. All seven fixes are now implemented and measured — this is the evidence, before and after, including where it still falls short.

527,072 OSM objects 10,427 events 38,331 attention series 4,884 scored localities

Before and after

Every number below is measured against a held-out reference set of 128 hand-labelled places, 35 of them negative controls — large, thoroughly mapped cities with no nomad reputation. Nothing in the model is tuned against these numbers.

Where it still falls short — read this

Rank correlation is still classified poor and hub/control separation only weak. The model still cannot cleanly separate a well-covered European city from a genuine secondary hub: Brussels sits at #11 and Milan at #29, above Chiang Mai at #61. Bansko and Chania remain near the bottom because no public event listing was found for them at all.

This is now a source limit, not a weighting one. Meetup's own coverage is geographically biased, and the coworking-feed layer is seeded from OSM website tags, so it inherits the same bias. No reweighting fixes a biased sample — that needs event sources with genuine reach outside Europe and North America.

The short answer

Nothing in the pipeline directly observes a digital nomad. There is no credential-free source that does. Every signal is a proxy, and the index is only as good as the gap between what the proxy measures and what you want to know. That gap is small at the top of the ranking and very large in the tail.

The core issue

The two strong sources cover only 361 localities. The two very weak ones cover all 34,900. The model's reach and the model's validity are inversely related.

2 · The evidence

Two-thirds of the evidence carries no nomad information

The ranking is not measuring city size — it is measuring map completeness

The good news first: the score is only weakly related to population (ρ = +0.31), so it is not a thinly disguised list of big cities. It tracks coworking density most strongly (ρ = +0.82), which is what you would want. The problem is what drives that.

This is the most reassuring result in the audit. The confidence model is doing its job: thin evidence is scored low and never reaches the top of the list. The multi-source, genuinely corroborated places are exactly the ones the map foregrounds. The 4,500 thin localities are not wrong so much as they are answering a different question — "does this town have amenities" — while sitting in a list titled "hottest right now".

The discovery loop is circular

Selection artifact

Event targets were chosen from the ecosystem-derived score. 53% of event-covered places were already in the top 400 before a single event was fetched. Places with event data have a median score of 66; comparable places without have a median of 18 and cannot exceed 58, because event activity is 25% of the model.

So the ranking substantially reflects which places I chose to look at. The system is presented as a discovery engine; on this evidence it is closer to a confirmation engine.

And the obvious fix does not work

The natural response is to strip out the generic infrastructure and score only on nomad-specific evidence. I ran that counterfactual. It makes things worse in an instructive way.

Counterfactual result

Re-ranking on coworking-per-capita, events and community alone puts Bordeaux (32.4 coworking per 100k), Porto (27.7), Lille (13.4) and Nantes (12.9) near the top — French and Portuguese provincial cities with unusually thorough OSM mapping. Chiang Mai improves (#106 → #39) but Las Palmas gets worse (#716 → #1025), as does Playa del Carmen (#185 → #501).

Conclusion: the dominant bias is not the tag mix — it is OSM completeness itself. No reweighting of OSM data can remove a bias that lives inside OSM. That requires either normalising against a mapping-density baseline, or evidence that is not OSM.

3 · What would actually bulletproof it

Ranked by how much validity each buys per unit of work. The first three are the ones that change the answer; the rest are hygiene.

  1. Normalise every OSM signal against a mapping-density baseline
    Effort LowImpact Very highFixes the root confound

    Compute total OSM object density per country (or per admin-1) from tags with no nomad relevance whatsoever — post boxes, benches, street lamps, building footprints — and divide every nomad signal by it. A city then scores on how unusually nomad-dense it is for how well its region is mapped. This is a few hours of work and it is the single change that would most improve trustworthiness.

  2. Break the circularity: sample event coverage randomly, not by rank
    Effort LowImpact HighFixes the discovery claim

    Reserve a large share of the event-scan budget for a stratified random sample across every region and city size, independent of the OSM score. That turns the event layer into an independent test of the ecosystem layer instead of a confirmation of it — and it is the only way an unknown hotspot can ever surface.

  3. Weight by nomad specificity, and stop counting sports centres
    Effort LowImpact MediumFixes the composition

    Drop sports_centre and community_centre entirely, or reduce them to a tiebreaker. On its own this is not sufficient — the counterfactual above proves that — but combined with (1) it stops civic amenity density masquerading as social ecosystem.

  4. Build a labelled validation set and measure against it
    Effort MediumImpact HighFixes “is it working?”

    Hand-label 60–100 places as strong / moderate / weak nomad destinations, publish the list, and report rank correlation against it on every build. Right now there is no number that says whether a model change made the index better or worse — which is exactly why this audit had to be done by hand. This turns validity from an opinion into a regression test.

  5. Add sources that are nomad-specific by construction
    Effort MediumImpact HighFixes the proxy gap

    All credential-free, all untested so far: public ICS and RSS calendars published by the coworking spaces the ecosystem layer has already located (the highest-value option — it converts a static venue into a live activity feed); nomad-focused Telegram channel web previews; coliving operator public listings; university international-office event calendars; and per-language Wikipedia attention rather than English only.

  6. Require corroboration before a place can rank
    Effort LowImpact MediumFixes the tail

    Gate the ranking on two or more independent source families. Everything else still renders on the map with its evidence, but as "infrastructure observed", not as a nomad score. The confidence model already gets this nearly right; this makes it explicit rather than emergent.

  7. Fix the matcher and disambiguate properly
    Effort LowImpact Low–mediumFixes known errors

    Replace the 5-character rule with country-qualified matching ("Ubud, Bali", "Goa, India"), require a second corroborating term in the post, and resolve Wikipedia titles through Wikidata coordinates rather than by population. That removes the Las Vegas / Goa class of error and unsilences 196 places.

What I would not claim even after all seven

Nomad population will still be unmeasurable without proprietary data. The product is already right to report presence as a band with a confidence rather than a headcount, and that should not change.
